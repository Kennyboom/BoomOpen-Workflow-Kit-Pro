# BoomOpen Workflow Kit Website

Marketing and documentation website for BoomOpen Workflow Kit, a multi-agent orchestration system for AI coding assistants.

## Features

- Dark theme with gradient accents
- Code splitting per route (lazy pages)
- Responsive layout (mobile, tablet, desktop)
- Accessibility work: skip link, keyboard navigation, focus management in the mobile menu,
  a single `<main>` landmark, muted text colour that meets WCAG AA contrast, and
  `prefers-reduced-motion` support (framer-motion `MotionConfig reducedMotion="user"`, decorative loops disabled)
- SEO: per-route title, description, canonical, Open Graph, Twitter and JSON-LD

## Development

```bash
npm install
```


## Where the content comes from

| Concern | Source of truth |
|---------|-----------------|
| Site origin (canonical, OG, JSON-LD, sitemap, robots) | `SITE_URL` in `src/components/seo/seo-config.ts` |
| Per-route title/description | `pageSEO` in `src/components/seo/seo-config.ts` |
| Kit version and counts (agents, teams, commands, skills, domains) | `src/data/kit-stats.json`, generated by `build/kit-stats.mjs` from the repository (`package.json`, `agents/`, `commands/`, `matrix-skills/`, `skills_library/`) |
| Install commands | `src/data/install.ts` |

`SITE_URL` still points at the previous Vercel host because the production domain has not been
decided. Change that one constant when the domain is known; everything else derives from it.

The kit is **not published on npm**. The site documents installing from a clone:

```bash
git clone https://github.com/Kennyboom/BoomOpen-Workflow-Kit.git
cd BoomOpen-Workflow-Kit
node cli/install.js install <tool>   # or: npm link, then boomopen install <tool>
```

### SEO at build and runtime

`build/site-plugin.ts` renders the home page head (title, meta, canonical, JSON-LD) into
`index.html`, writes `404.html` (noindex), `sitemap.xml` and `robots.txt`, and fails the build
when `vercel.json` does not rewrite every SPA route. At runtime `RouteSEO`
(`src/components/seo/SEO.tsx`) updates the same tags in place on every navigation, so each route
has exactly one of each tag.

## Hosting

`vercel.json` rewrites only the known SPA routes to `index.html`; unknown paths and missing assets
get a real 404 (`404.html`, noindex). It also sets security headers (CSP, `nosniff`,
`frame-ancestors 'none'`, Referrer-Policy, Permissions-Policy) and long-lived caching for the
hashed files in `/static/`.
