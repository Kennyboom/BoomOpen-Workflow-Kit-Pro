## 1. Core Concepts

### Orchestrator

| Attribute | Value |
|-----------|-------|
| **Definition** | The Smart-Hybrid AI coordination identity loaded by a platform entrypoint — executes `<= 2` known-file micro-tasks directly in `Mode A`, and shards, delegates, verifies, and synthesizes multi-agent workflows in `Mode B` |
| **Category** | Core Concepts |
| **Related Terms** | Smart-Hybrid Execution, Agent, 4-Tier Dynamic Elastic Swarm, Orchestration Laws |

Upon loading one of the `6` root entrypoints (`GEMINI.md`, `CLAUDE.md`, `CODEX.md`, `COPILOT.md`, `CURSOR.md`, `AGENT.md`), the AI operates under the Smart-Hybrid gate. Whenever target files are unknown on Turn 1, scope spans `> 2` files or `>= 2` domains, or an explicit `/cmd` or `17`-language workflow intent matches (`Mode B`), the AI acts strictly as the **Orchestrator** — never crawling or implementing solo, instead dispatching sharded specialist sub-agents and enforcing deterministic `boomopen` CLI gates.

### Agent

| Attribute | Value |
|-----------|-------|
| **Definition** | One of `21` specialist Markdown specifications (`agents/*.md`, `<= 450` lines each) defining an engineering, research, design, validation, or support role |
| **Category** | Core Concepts |
| **Related Terms** | Orchestrator, Team Agent, Shard Instance (`role#shard`), Profile, Handoff, Cognitive Anchor |

Each specialist agent is defined in `agents/{name}.md` with YAML frontmatter (`name`, `description`, `profile`, `handoffs`, `version: "5.5"`, `category`), a `<!-- COGNITIVE ANCHOR -->` block, thinking protocol, constraints, and verification gates. The `21` specialist agents are: `backend-engineer`, `brainstormer`, `business-analyst`, `database-architect`, `debugger`, `designer`, `devops-engineer`, `docs-manager`, `frontend-engineer`, `game-engineer`, `mobile-engineer`, `performance-engineer`, `planner`, `project-manager`, `reporter`, `researcher`, `reviewer`, `scouter`, `security-engineer`, `tech-lead`, and `tester`.

### Team Agent

| Attribute | Value |
|-----------|-------|
| **Definition** | A specialist role specification (`54` role files + `18` `_team.md` manifests = `72` files) inside one of the `18` domain team directories (`agents/teams/*-team/`) |
| **Category** | Core Concepts |
| **Related Terms** | Elastic Golden Diamond, Agent, Mailbox, Consensus Stamp |

Team files live under `agents/teams/{domain}-team/` (`backend-team`, `brainstorm-team`, `database-team`, `debug-team`, `design-team`, `devops-team`, `docs-team`, `frontend-team`, `fullstack-team`, `game-team`, `mobile-team`, `performance-team`, `planning-team`, `project-team`, `qa-team`, `report-team`, `research-team`, `security-team`) and define the **Lead**, **Executor**, and **Critic/Reviewer** pillars activated by `:team` command variants.

### Command

| **Category** | Core Concepts |

Commands connect user intent to deterministic multi-agent workflows. `BoomOpen Workflow Kit v5.5.0` ships `16` multi-variant command families (`/cook`, `/code`, `/plan`, `/design`, `/research`, `/brainstorm`, `/debug`, `/fix`, `/test`, `/review`, `/report`, `/docs`, `/deploy`, `/autopilot`, `/conduct`, `/ask`) and `16` standalone commands (`/settings`, `/orchestrate`, `/save`, `/recap`, `/init`, `/next`, `/status`, `/preview`, `/rollback`, `/architect`, `/auto`, `/refactor`, `/performance`, `/security-audit`, `/deep-audit`, `/ui-ux-pro-max`).

### Variant

## 2. Execution Model

### Smart-Hybrid Execution (`Mode A` & `Mode B`)

| Attribute | Value |
|-----------|-------|
| **Definition** | Dual-mode execution gate separating known-target micro-edits (`Mode A`, `<= 2` known files, `1` domain, `0` exploration) from multi-agent sharded orchestration (`Mode B`) |
| **Category** | Execution Model |
| **Related Terms** | 4-Tier Dynamic Elastic Swarm, Multilingual Intent Router, Orchestrator |

Controlled by `execution.mode` (`auto | mode_a | mode_b | team`) in `~/.boomopen/settings.json` and `./.boomopen.json`. Under default `auto` (**Proactive Sub-agent First**), unknown scope, `> 2` files, `>= 2` domains, `/cmd`, or any `17`-language workflow intent triggers `Mode B` on Turn 1.

### 4-Tier Dynamic Elastic Swarm & Cognitive Load Sharding Law

| Attribute | Value |
|-----------|-------|
| **Definition** | Dynamic sub-agent sizing formula capping each shard at `<= 3–4` heavy `OWNED_FILES` or `1` deep research/audit vector (`Tier 0`: `0` agents; `Tier 1`: `2–3`; `Tier 2`: `4–6`; `Tier 3`: `7–10+` up to `maxParallelSubagents`) |
| **Category** | Execution Model |
| **Related Terms** | Shard Instance (`role#shard`), 5-Field Handoff Packet, Elastic Golden Diamond |

Computed as $N_{\text{agents}} = \min(\text{maxParallelSubagents}, \max(\lceil \text{Files} / 3.5 \rceil, \text{Domains}, \text{Vectors}))$, preventing context degradation from overloading a single sub-agent with `> 4` files.

### Tiered Execution (`TIER 1` vs `TIER 2`)

| Attribute | Value |
|-----------|-------|
| **Definition** | Platform delegation hierarchy: `TIER 1` spawns isolated native sub-agents (`TypeName: "self"`, `Model: "inherit"`); `TIER 2` sequentially embodies `agents/{name}.md` only if native sub-agent tools are unavailable |
| **Category** | Execution Model |
| **Related Terms** | TIER 1, TIER 2, Embody, Quality-First Model Policy |

Using `TIER 2` when `TIER 1` sub-agent primitives exist is forbidden (`Anti-Pattern A5`).

### TIER 1

| Attribute | Value |
|-----------|-------|
| **Definition** | Primary parallel delegation tier spawning isolated sub-agent shards (`Role: "<role>#<shard>"`, `Model: "inherit"`) with full tool capabilities |
| **Category** | Execution Model |
| **Related Terms** | Tiered Execution, 5-Field Handoff Packet, Scoped Warm Session Reuse |

On Antigravity 2.0, `Mode B` shards use `invoke_subagent(TypeName: "self", Model: "inherit")` for 0-turn access to `write_file`, `run_command`, and `search_web` (reserving read-only `TypeName: "research"` strictly for 0-artifact ad-hoc codebase Q&A).

### TIER 2 & Embody

| Attribute | Value |
|-----------|-------|
| **Definition** | Tool-missing fallback where the Orchestrator logs `TIER 2`, reads `agents/{name}.md`, and sequentially embodies the specialist's Cognitive Anchor and 5-field locks |
| **Category** | Execution Model |
| **Related Terms** | Tiered Execution, TIER 1, Agent |

Even in `TIER 2`, all `OWNED_FILES` locks, `SHARED_CONTRACT` constraints, and `boomopen` CLI verification gates remain mandatory.

### 5-Field Handoff Packet

| Attribute | Value |
|-----------|-------|
| **Definition** | Mandatory prompt contract compiled by `boomopen cook packets` for every sub-agent shard: `1. MISSION & ACCEPTANCE CRITERIA`, `2. SHARED_CONTRACT`, `3. OWNED_FILES`, `4. READ_ONLY_FILES`, `5. VERIFICATION & DELIVERABLE` |
| **Category** | Execution Model |
| **Related Terms** | TIER 1, Phase & Wave, Deterministic CLI Gates |

Guarantees zero parallel write collisions (`OWNED_FILES` disjoint across sibling shards) and zero contract drift (`Wave 1` contracts/tokens locked inside `READ_ONLY_FILES`).

### Scoped Warm Session Reuse (`role#shard -> conversationId`)

| Attribute | Value |
|-----------|-------|
| **Definition** | Registry pattern tracking each spawned sub-agent shard's `conversationId` so follow-up waves, review debates, and `E2`/`E5` auto-repairs resume via `send_message` with `0s` cold-start |
| **Category** | Execution Model |
| **Related Terms** | TIER 1, Debate Mechanism, Error Classification (`E0–E6`) |

Cold re-spawning a duplicate sub-agent when a warm `role#shard` session already exists is prohibited (`Anti-Pattern A11`).

### On-Demand Rule Loading

| Attribute | Value |
|-----------|-------|
| **Definition** | Lazy-loading architecture where `rules/{CORE,PHASES,AGENTS,TEAMS,SKILLS,ERRORS,REFERENCE}.md` (`<= 300` lines each) are read only when `Mode B` needs them, replacing legacy mandatory Turn-1 multi-file pre-flights |
| **Category** | Execution Model |
| **Related Terms** | Platform Entry Point, Orchestrator |

Eliminates Turn-1 latency overhead while preserving full governance depth for complex orchestrations.

### Handoff

| Attribute | Value |
|-----------|-------|
| **Definition** | Permitted downstream specialist transitions declared in an agent's `handoffs: [...]` YAML frontmatter array |
| **Category** | Execution Model |
| **Related Terms** | Agent, Direct Plan-to-Executor Dispatch |

Combined with **Direct Plan-to-Executor Dispatch** (`L7`), validated `PLAN-{scope}.md` waves dispatch directly to domain shards without redundant middleman hops.

### Project Ledger (`.boomopen/project-ledger.json`)

| Attribute | Value |
|-----------|-------|
| **Definition** | Machine-verifiable multi-session DAG state file managed by `boomopen ledger` for `/autopilot`, enforcing RTM requirement coverage and SHA-256 Spec-Hash Drift Guards across sessions |
| **Category** | Execution Model |
| **Related Terms** | Command (`/autopilot`), 4-Layer Phase Ratchet (L9), Deterministic CLI Gates |

Persists phase status, `SHARED_CONTRACT` locks, and verification proofs across multi-session autonomous builds.

### Cross-Engine Conductor & Multi-Engine Council (`boomopen conduct`)

| Attribute | Value |
|-----------|-------|
| **Definition** | Cross-platform CLI orchestrator (`boomopen conduct <probe|dispatch|council|status>`) running `Author != Critic` cross-family pipelines and 6-task parallel councils (`claude`, `codex`, `antigravity`, `copilot`, `cursor`) |

Reconciles independent multi-engine outputs into `.boomopen/conductor/runs/<runId>-COUNCIL-SYNTHESIS.md` while guarding `READ_ONLY_FILES` with SHA-256 digests.
