## Must Have (10) — Core Smart-Hybrid Foundation

These 10 features are non-negotiable. Without any one of them, BoomOpen Workflow Kit cannot deliver its primary value proposition of multi-platform, specialist-driven AI orchestration.

| BF-ID | Feature | Rationale | Dependencies | Delivery Wave |
|-------|---------|-----------|--------------|---------------|
| `BF-001` | Source-Repository Global Installation & Ownership Ledgers | Entry point to the kit (`node cli/install.js install <tool|--all>`). Without manifest-safe global install, nothing loads. | Node.js `>=18.0.0` | Foundation Wave (`v5.5.0` ledger hardened) |
| `BF-002` | Unified 5-Platform Architecture | Multi-platform coverage (`BG-002`) across Antigravity, Claude Code, Codex, Cursor, and Copilot prevents single-tool lock-in. | `BF-001` (`platforms/*/` & CLI installer) | Foundation -> Unified Platform Wave (`v5.5.0`) |
| `BF-003` | Smart-Hybrid Orchestrator Pattern (`Mode A` vs. `Mode B`) | Defining architectural boundary: direct micro-edits (`<= 2` known files) vs. Proactive Sub-Agent First orchestration (`> 2` files / `>= 2` domains / `/cmd`). | `rules/CORE.md` & platform entrypoints | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-004` | 22 Specialist Agents & Quality-First Model Policy | Execution workforce (`agents/*.md`, `Model: "inherit"`). Without domain specialists, the Orchestrator has no expert roles to delegate to. | `BF-003` (Orchestrator delegation) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-005` | 36 Base Slash Commands (`93` Flat Command Files) | User-facing workflow playbooks (`87` in `commands/*.md` + `6` in `commands/_ref/*.md`). Provides deterministic phase routing. | `BF-003` (Orchestrator), `BF-004` (agents) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-006` | Multi-Tier Variant Strategies (`:fast`, `:hard`, `:team` + Specialized) | Right-sizes rigor and token cost to task complexity rather than forcing uniform overhead on every task. | `BF-005` (flat command routing) | Foundation -> Multi-Agent Wave (`v5.5.0`) |
| `BF-007` | 2-Step Progressive Skill Resolution (`HSOL v5.5` — `1,462` Skills) | Knowledge injection layer (`22` core + `1,440` library in `compact-index.json`). Eliminates idle prompt bloat while grounding domain work. | `BF-004` (agent profiles), `matrix-skills/` | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-008` | 4-Tier Dynamic Elastic Swarm & Tiered Execution | Cognitive Load Sharding (`<= 3–4` `OWNED_FILES`/shard) + TIER 1 parallel sub-agents (`TypeName: "self"`) with TIER 2 fallback. | `BF-003` (Orchestrator), `BF-004` (agents) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-009` | 10 Orchestration Laws (`L1–L10`) & Pragmatic 2-Tier Coding Standards | Formal session governance (`L1–L10`) plus Soft `400` / Hard `500` line budgets, zero explicit `any`, and zero production `console.log`. | `BF-003` (`rules/CORE.md`) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-010` | Cognitive Anchoring & Scoped Warm Session Reuse (`role#shard`) | Prevents persona drift (`AGENT-TEMPLATE.md`) and preserves multi-round context via `send_message` to warm `conversationId`s. | `BF-004` (`agents/*.md`), `BF-008` (shards) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |

### Must Have Dependency Chain

```
BF-001 (Install & Ledgers) -> BF-002 (5 Unified Platforms)
BF-001 (Install & Ledgers) -> BF-003 (Smart-Hybrid Orchestrator) -> BF-009 (L1-L10 & 2-Tier Standards)
BF-003 (Smart-Hybrid Orchestrator) -> BF-004 (22 Agents) -> BF-010 (Anchoring & Warm Reuse)
BF-003 (Smart-Hybrid Orchestrator) -> BF-005 (36 Base Commands / 93 Flat Files) -> BF-006 (Variants)
BF-003 (Smart-Hybrid Orchestrator) -> BF-008 (4-Tier Elastic Swarm & Tiered Execution)
BF-004 (22 Agents) -> BF-007 (HSOL v5.5 1,462-Skill Compact Index)
```

**Critical path**: `BF-001 -> BF-003 -> BF-004 -> BF-007`. If any link in this chain is absent, multi-agent domain orchestration collapses.

## Should Have (10) — Adversarial Quality, Governance & Control Plane

These 10 features differentiate BoomOpen Workflow Kit from prompt collections by enforcing adversarial review, deterministic CLI validation, self-healing recovery, 17-language intent routing, and unified configuration management.

| BF-ID | Feature | Rationale | Dependencies | Delivery Wave |
|-------|---------|-----------|--------------|---------------|
| `BF-011` | 18 Specialist Teams (Elastic Golden Diamond) | Adversarial 3-Pillar collaboration (`1 Lead + 1..6 Shards + 1..3 Critics`, `72` team files) elevates quality on complex changes. | `BF-004`, `BF-006` (`:team`), `BF-008` | Multi-Agent -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-012` | Error Self-Healing & Warm Auto-Revive (`E0–E6`) | Prevents silent failures and cold re-spawns via deterministic `E0–E6` recovery (`rules/ERRORS.md`). | `BF-008`, `BF-010` (`send_message`) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-013` | Dynamic Skill Discovery (`skill-seeker` & `_dynamic.yaml`) | Extends coverage beyond the `1,462` bundled skills for niche domains while falling back cleanly offline. | `BF-007` (`HSOL v5.5` fitness) | Vault Scale Wave (`v5.5.0`) |
| `BF-014` | Trust Progression Lifecycle | Gates external skills (`NEW -> EVALUATING -> VALIDATED -> PROMOTED`) so untested skills never override curated `1.0` skills. | `BF-013` (`_dynamic.yaml`) | Vault Scale Wave (`v5.5.0`) |
| `BF-015` | Multi-Pack Documentation Generation (`/docs`) | Automates Core (`5` folders), Business (`4` folders), and Audit documentation suites (`BG-010`). | `BF-004`, `BF-005` (`commands/docs-*.md`) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-016` | Append-Only Debate Mailbox & Consensus Stamp | Preserves auditable Round 1–3 critiques, defenses, and binding Tech Lead arbitration in `MAILBOX-{date}.md`. | `BF-011` (`18` teams) | Multi-Agent -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-017` | 17-Language Natural-Language Intent-to-Workflow Router | Maps plain-language prompts across all `17` supported languages directly to canonical Mode B workflows without memorizing slash syntax. | `BF-005` (`93` flat command files) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-018` | Multilingual Response & Localization Suite (`Law L6` + `17` Locales) | Responds in the user's language while keeping source code in English, backed by `17` localized README editions. | `BF-009` (`Law L6`) | Foundation -> Smart-Hybrid Wave (`v5.5.0`) |
| `BF-024` | 3-Surface Unified Settings & Mode Control Center (`/settings` & Web UI) | Controls `5` core presets (`frontier-guardrails` default), `20` enum keys + `2` line-limit keys, and `< 10ms` AOT hot-sync across all 5 platforms via chat, CLI, or CSP-hardened Web UI. | `BF-001`, `BF-002` | Current Release (`v5.5.0`) |
| `BF-025` | Deterministic CLI Compilers, Validators & CI Quality Gates | Machine-verifiable `research`/`design`/`plan`/`cook`/`reconcile`/`audit`/`check`/`doctor` gates + `34` `node:test` suites + Cross-OS GitHub Actions CI. | `BF-001`, `BF-005`, `BF-009` | Smart-Hybrid -> Current Release (`v5.5.0`) |

These 7 capabilities extend BoomOpen Workflow Kit into deployment automation, hands-off routing, instant plan fast-forwarding, platform health diagnostics, multi-session project ledgers, and multi-engine model councils. **All 7 are fully implemented and shipped in `v5.5.0`.**

| BF-ID | Feature | Rationale | Dependencies | Status (`v5.5.0`) |
|-------|---------|-----------|--------------|-------------------|
| `BF-019` | Structured Deployment Workflows (`/deploy`) | Adds pre-deploy checks, preview staging, production release, and rollback alongside existing CI/CD pipelines. | `BF-004` (`devops-engineer`), `BF-005` | Delivered (`v5.5.0`) |
| `BF-020` | Autonomous Self-Routing Execution (`/auto` & `/orchestrate`) | Hands-off classification and swarm execution for experienced users who prefer minimal checkpoints. | `BF-004` (`tech-lead`), `BF-005`, `BF-008` | Delivered (`v5.5.0`) |
| `BF-021` | Grounded Reporting System (`/report`) | Automates repository-grounded status and metrics reports (`:fast`, `:hard`, `:team`). | `BF-004` (`reporter`, `scouter`), `BF-005` | Delivered (`v5.5.0`) |
| `BF-022` | 5-Stage Fast-Forward & Approved-Plan Execution (`cook state|packets`) | Skips redundant scouting/planning when artifacts exist and compiles 5-Field Wave Handoff Packets on **"Proceed"**. | `BF-005` (`/code`, `/cook`), `BF-025` (`cli/cook.js`) | Delivered (`v5.5.0`) |
| `BF-023` | CLI Platform Inventory & Health Diagnostics (`boomopen list` & `doctor`) | Inspects live install status across all 5 platforms and audits Markdown budgets, `compact-index.json`, and settings. | `BF-001` (`cli/install.js`), `BF-002` | Delivered (`v5.5.0`) |
| `BF-026` | Multi-Session Autonomous Project Autopilot (`/autopilot` & `ledger`) | Manages multi-phase roadmaps via `.boomopen/project-ledger.json` with SHA-256 Spec-Hash Drift Guard across sessions. | `BF-005`, `BF-025` (`plan`/`check` gates) | Delivered (`v5.5.0`) |
| `BF-027` | Cross-Engine Autonomous Conductor & Multi-Engine Council (`/conduct`) | Orchestrates Claude, Codex, Antigravity, Cursor, and Copilot in `Author != Critic` pipelines and 6-task consensus councils. | `BF-002`, `BF-011`, `BF-025` | Delivered (`v5.5.0`) |

## Priority Justification Matrix

| BF-ID | Without It... | MoSCoW |
|-------|---------------|--------|
| `BF-001` | Kit cannot be installed safely across global tool directories | Must |
| `BF-002` | Locked into a single AI coding tool | Must |
| `BF-003` | Primary agent crawls files solo or over-orchestrates 1-file edits | Must |
| `BF-004` | No domain specialists or `Model: "inherit"` quality floor | Must |
| `BF-005` | No standardized engineering workflow playbooks | Must |
| `BF-006` | Every task pays identical latency and token cost | Must |
| `BF-007` | Agents either lack domain skills or suffer massive prompt bloat | Must |
| `BF-008` | Single sub-agents overload on `> 4` files or fail on non-subagent hosts | Must |
| `BF-009` | Session governance and 2-Tier code standards drift unpredictably | Must |
| `BF-010` | Specialists lose persona boundaries and cold-restart every round | Must |
| `BF-011` | Single-perspective execution without adversarial 3-Pillar critique | Should |
| `BF-012` | Interrupted shards (`E0`) or gate failures (`E5`) stall without auto-repair | Should |
| `BF-013` | Restricted strictly to bundled skills until next repository release | Should |
| `BF-014` | Unvetted dynamic skills could rank equal to curated core skills | Should |
| `BF-015` | Technical and business documentation suites must be written manually | Should |
| `BF-016` | Multi-agent critiques lack an auditable trail or round cap | Should |
| `BF-017` | Global users must type explicit slash commands instead of natural language | Should |
| `BF-018` | Non-English developers lose native-language guidance or pollute code comments | Should |
| `BF-019` | Teams rely solely on manual/external release checklists | Could |
| `BF-020` | Users manually select workflow commands on every invocation | Could |
| `BF-021` | Project status and audit reports are compiled manually | Could |
| `BF-022` | Approved plans re-trigger redundant scouting or manual packet assembly | Could |
| `BF-023` | Users inspect `5` platform dotfiles and `compact-index.json` by hand | Could |
| `BF-024` | Tuning presets, swarm limits, or engines requires manual file edits | Should |
| `BF-025` | Deliverables and waves rely on LLM self-checks instead of `< 50ms` CLI gates | Should |
| `BF-026` | Multi-phase project specs lose state and drift across chat sessions | Could |
| `BF-027` | High-stakes reviews and deadlocks remain confined to one model family | Could |
