## Quick Summary

This PRD defines the product requirements for **`@boomopen/workflow-kit` `v5.5.0` (BoomOpen Workflow Kit v5.5 — Multi-Platform Unified & Smart-Hybrid Edition)**, a multi-agent orchestration framework that transforms an AI coding assistant into a coordinated swarm of **21 specialist agents** and **18 Elastic Golden Diamond teams** across **5 unified platforms** (Antigravity/Gemini, Claude Code, OpenAI Codex, Cursor, and GitHub Copilot). The framework ships **32 base slash commands** across **84 flat command files** (`79` workflow files in `commands/*.md` + `5` shared protocol files in `commands/_ref/*.md`), **17-language natural-language intent routing** (`16` `i18n/README.*.md` guides + English `README.md`), a **Hybrid Skill Orchestration Layer (`HSOL v5.5`)** indexing **1,462 skills** (`22` pre-loaded Core Skills in `skills/` + `1,440` dormant Library Skills in `skills_library/` across `19` domains via `O(1)` `matrix-skills/compact-index.json` lookup), and **12 deterministic `boomopen` CLI subcommands** (`install`, `uninstall`, `list`, `settings`, `doctor`, `check`, `research`, `design`, `plan`, `cook`, `ledger`, `conduct`). Installation is source-only via Git (`https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro`, `npmPublish: false`), global, and one-time with SHA-256 ownership manifests and zero required per-project setup.

The PRD covers 10 business goals (BG-001 through BG-010), 7 stakeholder types, 23 functional requirements (BR-001 through BR-023) with INVEST scoring, acceptance criteria, and a risk register distinguishing verified CLI/CI guarantees (`30` `node:test` suites + cross-OS GitHub Actions CI) from unvalidated end-to-end productivity targets and optional external services.

## Known Gaps

| ID | Gap | Impact | Affected Items |
|----|-----|--------|----------------|
| GAP-001 | End-to-end productivity claims (70% faster, 70% fewer bugs, 85% token savings) remain design targets without standardized task benchmarks in the repository | Stakeholder expectations may exceed measured results if treated as guaranteed benchmarks | BG-003, BG-004, BG-005, BR-003, BR-008 |
| GAP-002 | While `30` `node:test` suites and deterministic CLI gates (`research`, `design`, `plan`, `cook`, `check`, `ledger`, `conduct`, `doctor`) validate artifacts and CLI behavior, live LLM prompt adherence varies across model providers | Model-specific behavioral drift outside deterministic CLI gates must be caught during manual cross-model verification or Cross-Engine Council runs | BG-002, BG-004, BR-012, BR-013 |
| GAP-003 | Optional dynamic skill discovery (`npx skills find` / `skills.sh`) depends on an external service not bundled with the repository | External skill discovery degrades gracefully to the `1,462` bundled local skills when offline or unreachable | BG-007, BG-009, BR-009, BR-010 |
| GAP-004 | Trust Progression Lifecycle (`NEW 0.3 → EVALUATING 0.5 → VALIDATED 0.7 → PROMOTED 1.0` in `matrix-skills/_dynamic.yaml`) is schema-defined rather than automatically incremented by runtime telemetry | Skill promotion requires explicit maintainer curation | BG-007, BG-009, BR-010 |
| GAP-005 | No public multi-quarter roadmap board is published outside release notes | External contributors have limited visibility into post-`v5.5.0` feature sequencing | BG-009, BG-010 |
| GAP-006 | Community skill count target (`>= 50` within 12 months) has no built-in registry analytics | BG-009 community growth must be audited externally on `skills.sh` or GitHub | BG-009 |
| GAP-007 | Team adoption metric (`>= 80%` within 30 days) has no built-in telemetry by design (zero-telemetry privacy guarantee) | Organizations must track adoption via internal developer surveys or `.boomopen.json` usage | BG-002 |
