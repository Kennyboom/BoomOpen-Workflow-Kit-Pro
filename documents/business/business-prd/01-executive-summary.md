## Mission Statement

BoomOpen Workflow Kit (`v5.5.0` — Multi-Platform Unified & Smart-Hybrid Edition) transforms an AI coding assistant into a coordinated, elastically sharded team of specialist agents backed by deterministic CLI compilers and validators — eliminating repetitive prompt engineering and enforcing Pragmatic 2-Tier quality governance from a one-time, source-only global Git installation with zero mandatory per-project configuration.

---

## Value Proposition

### For Individual Developers

One source install. Every project. BoomOpen Workflow Kit clones from `https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro` (`https://boomopen.com`, `npmPublish: false`) and installs into your AI tool's global directories (`~/.gemini/` & `~/.antigravity/`, `~/.claude/`, `~/.codex/`, `~/.cursor/`, `~/.copilot/`, sharing a deduplicated `~/.agents/skills_library/` vault) with SHA-256 per-file ownership manifests (`~/.boomopen/manifests/<tool>.json`) and automatic user backups (`~/.boomopen/backups/`). Developers can either invoke **36 base slash commands** (`/cook`, `/code`, `/plan`, `/design`, `/research`, `/brainstorm`, `/fix`, `/debug`, `/test`, `/review`, `/audit`, `/pr`, `/onboard`, `/release`, `/autopilot`, `/conduct`, `/settings`, etc.) or speak naturally in **any of 17 supported languages** — the Smart-Hybrid router handles known-file edits directly (Mode A; `< 2.5 KB` Slim Guardrails by default under `frontier-guardrails`) and fans out complex tasks across parallel `role#shard` specialists locked to `<= 3–4 OWNED_FILES` each (Mode B). Configuration is available across 3 surfaces: `/settings`, `boomopen settings`, and the CSP-hardened Local Web UI (`boomopen settings --ui` on `http://127.0.0.1:4567`) across `5` core presets.

The framework states design targets of 70% faster time-to-production, 70% bug reduction, and 85% token cost savings via focused specialist profiles, 2-Step `O(1)` skill lookup (`matrix-skills/compact-index.json`), and 5-Stage Fast-Forward artifact reuse. End-to-end task percentages remain unvalidated design targets without standardized task benchmarks.

### For Teams and Organizations

The `:team` variant activates the **18 Elastic Golden Diamond teams** (`72` files across `agents/teams/*-team/`, including `brainstorm-team`), scaling elastically from `1-1-1` (`3` agents for `<= 4` files) up to `1 Tech Lead + 1..6 Parallel Shard Executors + 1..3 Parallel Critics` with structured debate (max `3` rounds), consensus stamps, `MAILBOX` / Brain Artifact audit trails, Cross-Engine Conductor (`Author != Critic`) verification (`boomopen conduct`), and deterministic CLI gates (`boomopen research|design|plan|cook|reconcile|audit|check|ledger`). Teams can also commit an optional `./.boomopen.json` profile to standardize workflow presets across a repository.

### For the Ecosystem

Skill Authors author reusable `SKILL.md` domain packages indexed via `skill-seeker` (`skills/skill-seeker/`) and `matrix-skills/compact-index.json` (`1,462` bundled skills = `22` Core + `1,440` Library across `19` domains) or shared externally through `skills.sh`. The Trust Progression Lifecycle (`NEW → EVALUATING → VALIDATED → PROMOTED`) defines quality gates for promoting community skills into curated domain matrices.

## Target Users

### Primary: Individual Developer (Framework User)

- **Profile**: Software developer using one or more AI coding assistants daily
- **Need**: Eliminate repetitive prompt engineering; obtain consistent, verified deliverables across languages and projects
- **Touchpoints**: Source Git installer (`node cli/install.js install --all` / `boomopen install`), `36` base slash commands, `17`-language natural-language routing, 3-Surface `/settings` (`boomopen settings --ui` on port `4567`)
- **Goals served**: BG-001 (one-time setup), BG-003 (faster delivery), BG-004 (fewer bugs), BG-005 (lower token cost), BG-006 (structured workflows)

### Secondary: Team/Organization Lead

- **Profile**: Technical lead or engineering manager standardizing AI-assisted engineering governance
- **Need**: Enforced coding standards, disjoint file ownership locks, adversarial code/design review, and multi-session project tracking
- **Touchpoints**: `:team` and `:hard` variants, `./.boomopen.json` workspace config, `18` Elastic Golden Diamond teams, `boomopen check --strict-phase --no-stubs`, `boomopen ledger`, `boomopen conduct`, `MAILBOX` & Brain Artifacts
- **Goals served**: BG-002 (consistent practices), BG-004 (fewer bugs), BG-008 (adversarial collaboration)

### Tertiary: Skill Author

- **Profile**: Domain specialist authoring reusable AI workflow skills
- **Need**: Standardized `SKILL.md` packaging, fast local indexing, and a clear promotion path
- **Touchpoints**: `SKILL.md` format, `skills/skill-seeker/`, `matrix-skills/compact-index.json` (`boomopen doctor --rebuild-index`), optional `skills.sh` ecosystem, `matrix-skills/_dynamic.yaml` Trust Progression Lifecycle
- **Goals served**: BG-007 (skill resolution), BG-009 (community ecosystem)

### Enabling: AI Model (Runtime)

- **Profile**: The underlying LLM runtime (Claude, Gemini, GPT/Codex, etc.) executing framework instructions
- **Need**: Concise zero-latency entrypoints (`<= 250` lines), on-demand rules (`<= 300` lines), and explicit 5-Field Handoff Packets (`MISSION`, `SHARED_CONTRACT`, `OWNED_FILES`, `READ_ONLY_FILES`, `VERIFICATION`)
- **Touchpoints**: `6` root entrypoints (`GEMINI.md`, `CLAUDE.md`, `CODEX.md`, `COPILOT.md`, `CURSOR.md`, `AGENT.md`), `7` `rules/*.md` files, `22` `agents/*.md` profiles, `matrix-skills/compact-index.json`
- **Goals served**: BG-007 (auto skill injection), all goals indirectly as the execution engine

### Supporting: Platform Maintainer

- **Profile**: Engineer maintaining instruction/skill loading in Antigravity, Claude Code, Codex, Cursor, or GitHub Copilot
- **Need**: Non-destructive, manifest-tracked integration with platform configuration conventions
- **Touchpoints**: `platforms/{antigravity,claude,codex,copilot,cursor}/`, `cli/install.js`, SHA-256 ledgers (`~/.boomopen/manifests/<tool>.json`), marked settings/kit blocks
- **Goals served**: BG-002 (multi-platform support)

### Governing: Framework Maintainer (BoomOpen Labs / Kennyboom)

- **Profile**: Maintainer governing `Kennyboom/BoomOpen-Workflow-Kit-Pro` architecture, quality gates, and releases
- **Need**: Deterministic CI verification across OS/Node matrices and guarded source-only GitHub releases
- **Touchpoints**: `cli/*.js` (`49` modules), `34` `node:test` suites, `.github/workflows/ci.yml`, `.github/workflows/release.yml` (`.releaserc.json` with `npmPublish: false`)
- **Goals served**: BG-009 (ecosystem governance), BG-010 (extensibility & documentation)

### Contributing: Contributor

- **Profile**: Open-source developer adding specialist agents, flat workflow commands, localized guides, or domain skills
- **Need**: Clear file-size budgets, templates, and instant local health validation
- **Touchpoints**: `AGENT-TEMPLATE.md`, flat `commands/{cmd}-{variant}.md` convention (`<= 450` lines), `SKILL.md`, `boomopen doctor`
