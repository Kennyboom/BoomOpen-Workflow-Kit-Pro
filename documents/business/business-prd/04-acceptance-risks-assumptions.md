## Acceptance Criteria

### AC-001: Global Source-Only Installation & Manifest Ownership

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-001, BR-001, BR-023, BF-001, BF-023 |
| **Given** | A machine with Git and Node.js `>= 18.0.0` |
| **When** | User runs `git clone https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro.git && cd BoomOpen-Workflow-Kit-Pro && node cli/install.js install --all` (or `npm link` followed by `boomopen install --all`) |
| **Then** | Framework bundles exist across all 5 platform destinations (`~/.gemini/config/skills/boomopen-workflow-kit/`, `~/.claude/skills/boomopen-workflow-kit/`, `~/.codex/skills/boomopen-workflow-kit/`, `~/.cursor/skills/boomopen-workflow-kit/`, `~/.copilot/skills/boomopen-workflow-kit/`), shared `~/.agents/skills_library/` vault is populated, SHA-256 ownership manifests exist at `~/.boomopen/manifests/<tool>.json`, `boomopen doctor` exits `0`, and total install time is `<= 5` minutes |

### AC-002: Multi-Platform Parity

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-002, BR-002, BF-002 |
| **Given** | `@boomopen/workflow-kit` `v5.5.0` is installed across all 5 platforms |
| **When** | Antigravity (Gemini), Claude Code, OpenAI Codex, Cursor, or GitHub Copilot opens any workspace |
| **Then** | The platform's `<= 250`-line `v5.5` Smart-Hybrid entrypoint (or `< 2.5 KB` `frontier-guardrails` Slim Guardrail) loads with active `BOOMOPEN-SETTINGS` markers, exposing the same `36` base slash commands (`93` flat command files), `22` specialist agents, `18` Elastic Golden Diamond teams, `1,462` skills, and `17`-language natural-language routing |

### AC-003: Smart-Hybrid Orchestrator Delegation & Cognitive Sharding

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-003, BG-004, BR-003, BR-012, BF-003, BF-012 |
| **Given** | A loaded `v5.5` Smart-Hybrid entrypoint on any supported platform |
| **When** | User submits a request via explicit `/cmd` or natural language in any of the `17` supported languages |
| **Then** | Known-target micro-edits touching `<= 2` files in `1` domain execute directly under Pragmatic 2-Tier Coding Standards (Mode A), whereas any task spanning `> 2` files, `>= 2` domains, unscoped exploration, or a workflow intent routes immediately on Turn 1 to parallel `role#shard` specialists (`<= 3–4 OWNED_FILES` per shard) with 5-Field Handoff Packets (Mode B) — zero primary-agent solo crawling (`A1`) |

### AC-004: Specialist Agent Completeness

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-004, BR-004, BR-021, BF-004, BF-021 |
| **Given** | The `agents/` directory |
| **When** | All `22` specialist agent files (`agents/*.md`) are audited by `boomopen doctor` |
| **Then** | Every agent file is `<= 450` lines, free of mojibake or legacy paths, and defines distinct role metadata, thinking/execution protocols, ownership boundaries, and verification deliverables |

### AC-005: Flat Command Routing & Deterministic CLI Compilers

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-006, BR-006, BR-007, BR-015, BR-016, BF-006, BF-007, BF-015, BF-016 |
| **Given** | The flat `commands/` directory (`87` `commands/*.md` + `6` `commands/_ref/*.md` = `93` files covering `36` base commands) |
| **When** | A command or 17-language workflow intent is triggered |
| **Then** | The matching `commands/{cmd}-{variant}.md` workflow executes Turn-1 Instant Dispatch, fast-forwards past already-validated artifacts (`boomopen cook state`), validates `RESEARCH`/`BRAINSTORM` (`RES-G1..G4`), `DESIGN` (`DESIGN-G1..G4`), and `PLAN` (`PLAN-G1..G5`), and enforces post-wave locks via `boomopen cook verify-wave`, `boomopen reconcile` (`REC-G1..G4`), and `boomopen check --strict-phase --no-stubs` |

### AC-006: `HSOL v5.5` 2-Step `O(1)` Skill Resolution

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-005, BG-007, BR-008, BF-008 |
| **Given** | A complex task requiring framework or domain specialization |
| **When** | `HSOL v5.5` skill resolution runs |
| **Then** | Step 1 checks the `22` pre-loaded Core Skills in `<skills>` (`0` latency), and if a niche skill is needed, Step 2 queries `matrix-skills/compact-index.json` (`1,462` skills across `19` domains) via `skill-seeker` and loads only the matched `SKILL.md` from `skills_library/` without scanning full YAML matrices |

### AC-007: Elastic Golden Diamond Team Protocol

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-008, BR-005, BR-014, BF-005, BF-014 |
| **Given** | Any `:team` workflow variant is invoked across the `18` specialist teams (`72` files in `agents/teams/*-team/`) |
| **When** | Team phases execute |
| **Then** | The swarm scales elastically from `1-1-1` (`3` agents for `<= 4` files) up to `1 Tech Lead + 1..6 Parallel Shard Executors (role#shard, <= 3–4 OWNED_FILES each) + 1..3 Parallel Critics`, records structured adversarial findings in `MAILBOX` / Brain Artifacts, caps debate at `3` rounds (`teams.maxDebateRounds = 3`) with binding Tech Lead arbitration, and requires a Consensus Stamp before wave release |

### AC-008: Deterministic Error Self-Healing (`E0–E6`)

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-004, BR-013, BF-013 |
| **Given** | An interruption, build failure, or CLI gate failure occurs during execution |
| **When** | The error is classified under `rules/ERRORS.md` (`E0–E6`) |
| **Then** | `E0` auto-revives interrupted warm shards via `send_message`; `E1` retries transient tool errors (`<= 3x`); `E1b` keeps Brain Artifacts cohesive (`<= 500` lines) or compiles epics into `.boomopen/project-ledger.json`; `E2` routes exact `File:Line` build/`check` errors back to the owning warm `role#shard`; `E3` resolves or escalates blocking contract conflicts via `ask_question`; `E4` rolls back cross-shard drift and broadcasts updated `SHARED_CONTRACT`; `E5` repairs failed `research`/`design`/`plan`/`cook`/`reconcile`/`audit`/`ledger` CLI gates until exit `0`; `E6` escalates round-2 deadlocks to a second model family via `boomopen conduct dispatch`. Execution never halts silently |

### AC-009: Tiered Execution & Warm Session Reuse

| Attribute | Detail |
|-----------|--------|
| **Covers** | BG-003, BG-005, BR-011, BF-011 |
| **Given** | A Mode B delegation request to a specialist shard (`role#shard`) |
| **When** | Native sub-agent tools exist on the host platform |
| **Then** | `TIER 1` sub-agents spawn with `Model: "inherit"` (Pro High default; `"flash_lite"` forbidden), `role#shard -> conversationId` is tracked in the Active Sub-agent Session Registry for warm follow-ups via `send_message`, and `TIER 2` embodiment is used strictly as a logged fallback when sub-agent primitives are unavailable |

## Risk Register

### RISK-001: Unvalidated End-to-End Productivity Claims

| Attribute | Detail |
|-----------|--------|
| **Category** | Credibility / Positioning |
| **Description** | Product materials cite design targets of 70% faster time-to-production, 70% bug reduction, and 85% token cost savings without a reproducible task benchmark suite in the repository. |
| **Probability** | High — numbers appear prominently in product summaries |
| **Impact** | Medium–High — adopters may treat architectural targets as guaranteed empirical benchmarks |
| **Affected Goals** | BG-003, BG-004, BG-005 |
| **Affected Requirements** | BR-003, BR-008 |
| **Mitigation** | Explicitly label 70%/70%/85% figures as **unvalidated design targets** throughout PRD/business docs and establish a standardized A/B task benchmark suite in future releases. |
| **Status** | Open — documented transparently as design targets in PRD |

### RISK-002: Optional External Dependency on `skills.sh`

| Attribute | Detail |
|-----------|--------|
| **Category** | Availability / Ecosystem |
| **Description** | Dynamic external skill discovery (`npx skills find` / `skills.sh`) and public community skill metrics depend on a third-party service outside repository control. |
| **Probability** | Medium — external registries may experience downtime or CLI changes |
| **Impact** | Low–Medium — `1,462` skills (`22` Core + `1,440` Library) are bundled locally and indexed in `matrix-skills/compact-index.json` for 100% offline operation |
| **Affected Goals** | BG-007, BG-009 |
| **Affected Requirements** | BR-009, BR-010 |
| **Mitigation** | Primary skill resolution uses local `<skills>` + `compact-index.json` (`skill-seeker`); external `npx skills` lookup is optional and degrades gracefully under `E1` recovery. |
| **Status** | Mitigated for core workflows — local `1,462`-skill vault is self-contained |

### RISK-003: Prompt-Layer LLM Behavioral Drift Outside Deterministic CLI Gates

| Attribute | Detail |
|-----------|--------|
| **Category** | Quality / Runtime Consistency |
| **Description** | In `v5.5.0`, `14` `boomopen` CLI subcommands and `34` `node:test` suites (`33` `cli/*.test.js` + `web/build/kit-stats.test.mjs`) deterministically verify installation safety, Markdown budgets, `RESEARCH`/`DESIGN`/`PLAN` contracts, wave ownership locks, spec reconciliation (`REC-G1..G4`), and anti-stub code quality in CI (`.github/workflows/ci.yml`). However, Turn-1 routing decisions and conversational adherence inside the LLM runtime still rely on model instruction-following fidelity. |
| **Probability** | Medium — LLM providers periodically update model weights and tool-calling heuristics |
| **Impact** | Medium — structural contract violations are caught by `boomopen` CLI gates (`E5`) and `PreToolUse`/`Stop` hooks (`--with-hooks`), though sub-optimal routing could still occur on weaker models |
| **Affected Goals** | BG-002, BG-004, BG-006 |
| **Affected Requirements** | BR-003, BR-011, BR-012 |
| **Mitigation** | Enforce `Model: "inherit"` (Pro High default, `"flash_lite"` forbidden), gate every artifact/wave through `boomopen research\|design\|plan\|cook\|reconcile\|check`, and use `--with-hooks` (`validate-tool-call.mjs` & `stop-quality-gate.mjs`) where supported. |
| **Status** | Partially mitigated — CLI & artifact gates automated in CI; live LLM routing remains model-dependent |

### RISK-004: Absence of a Public Multi-Quarter Roadmap Board

| Attribute | Detail |
|-----------|--------|
| **Category** | Community / Adoption |
| **Description** | While `CHANGELOG.md` documents shipped capabilities through `v5.5.0`, no public GitHub Project board or multi-quarter roadmap tracks upcoming milestones. |
| **Probability** | High — confirmed absent in repository |
| **Impact** | Low–Medium — external contributors lack visibility into upcoming post-`v5.5.0` priorities |
| **Affected Goals** | BG-009, BG-010 |
| **Mitigation** | Publish milestone priorities in GitHub Discussions or a `ROADMAP.md` companion file. |
| **Status** | Open |

### RISK-005: Schema-Only Trust Progression Tracking

| Attribute | Detail |
|-----------|--------|
| **Category** | Feature Completeness |
| **Description** | `matrix-skills/_dynamic.yaml` defines the Trust Progression states (`NEW 0.3 → EVALUATING 0.5 → VALIDATED 0.7 → PROMOTED 1.0`), but transitions are not automatically mutated at runtime because the kit runs zero background daemons or telemetry. |
| **Probability** | Medium — runtime state mutation is intentionally manual/CLI-driven |
| **Impact** | Low — affects only newly added community skills outside the `1,462` curated vault |
| **Affected Goals** | BG-009 |
| **Affected Requirements** | BR-010 |
| **Mitigation** | Document trust progression as maintainer/CLI-governed curation or add an explicit `boomopen` skill-promotion helper in a future release. |
| **Status** | Open — documented accurately |

### RISK-006: Cross-Model Reasoning Blind Spots

| Attribute | Detail |
|-----------|--------|
| **Category** | Technical / Multi-Model Reliability |
| **Description** | Different model families (Claude, Gemini, GPT/Codex) exhibit distinct reasoning strengths and blind spots on complex root-cause bugs or architectural trade-offs. |
| **Probability** | Medium — inherent to heterogeneous LLM runtimes |
| **Impact** | Medium — single-family retries can stall on Heisenbugs or subtle design flaws |
| **Affected Goals** | BG-002, BG-004, BG-008 |
| **Affected Requirements** | BR-003, BR-013, BR-014, BR-019 |
| **Mitigation** | `v5.5.0` ships `boomopen conduct` (`Author != Critic` cross-family pipelines, 6-task Multi-Engine Council synthesis, and `E6` round-2 cross-engine debugger escalation). |
| **Status** | Mitigated when multiple CLI engines are installed (`boomopen conduct probe`) |

### RISK-007: Upstream AI IDE Config Format Changes

| Attribute | Detail |
|-----------|--------|
| **Category** | Compatibility / Maintenance |
| **Description** | Antigravity, Claude Code, OpenAI Codex, Cursor, or GitHub Copilot may alter global rule paths, TOML schemas, or prompt folder conventions in future IDE releases. |
| **Probability** | Medium — AI coding tools evolve rapidly |
| **Impact** | High — an unadapted path change could prevent automatic entrypoint loading on the affected platform |
| **Affected Goals** | BG-002 |
| **Affected Requirements** | BR-002 |
| **Mitigation** | Platform-specific adapters are isolated in `platforms/*` and `cli/install-*.js`, backed by SHA-256 manifests, legacy-path cleanup repairs (`cli/install-repairs.test.js`), and `boomopen doctor`. |
| **Status** | Actively managed via `cli/platform-content.test.js` & `boomopen doctor` |

## Assumptions

| ID | Assumption | Impact if Invalid | Validation Method |
|----|------------|-------------------|-------------------|
| A-001 | Supported AI coding assistants continue loading global markdown/TOML/rule files from user home directories | Global one-time installation model would require per-workspace fallback | Monitor upstream release notes for all 5 platforms |
| A-002 | Developers have Git and Node.js `>= 18.0.0` installed locally | CLI installer and deterministic compilers cannot execute on older Node runtimes | Cross-OS CI matrix tests Node `18`, `20`, and `22` |
| A-003 | Developers accept cloning the source-only Git repository (`Kennyboom/BoomOpen-Workflow-Kit-Pro`) and running a one-time global CLI install (`node cli/install.js install --all` or `npm link`) | Users expecting `npm install -g` without cloning could encounter onboarding friction unless guided by `README.md` | Prominent quick-start instructions across `README.md` and `16` `i18n/README.*.md` files |
| A-004 | Antigravity, Claude Code, OpenAI Codex, Cursor, and GitHub Copilot represent the primary AI coding assistant market | Uncovered niche IDEs must rely on root `AGENT.md` manual loading | Periodic developer tooling market review |
| A-005 | Frontier Pro-tier models (`Model: "inherit"`) reliably follow `<= 250`-line entrypoints and 5-Field Handoff Packets | Higher gate-repair retry rate (`E5`) during multi-wave execution | Validated iteratively by `boomopen research\|design\|plan\|cook\|check` CLI gates |
| A-006 | The `1,462` bundled skills (`22` Core + `1,440` Library across `19` domains) cover the vast majority of production engineering stacks | Niche stacks fall back to first-principles research (`deep-research`) or optional `skills.sh` lookup | Periodic domain audit via `cli/vault-content.test.js` |
| A-007 | External skill authors continue adopting the `SKILL.md` frontmatter + Markdown convention | Community skills would require adapter normalization before indexing | `boomopen doctor --rebuild-index` schema checks |
| A-008 | Elastic Golden Diamond adversarial review (`Tech Lead + Shard Executors + Critics`) and Cross-Engine Council (`Author != Critic`) catch defects missed by solo sessions | Added multi-agent turn cost would yield diminishing returns on trivial tasks (avoided via Mode A & `:fast`) | Smart-Hybrid Mode A/B threshold (`<= 2` known files bypasses swarm overhead) |
| A-009 | Guarded manual Semantic Release (`.github/workflows/release.yml` + `.github/scripts/release-guard.js`, `npmPublish: false`) with Conventional Commits keeps `CHANGELOG.md` and GitHub Releases accurate | Malformed commits could skip release notes if commit conventions are ignored | Release guard script + CI checks before release |
| A-010 | Contributors can author and validate a new agent, flat command, or skill in `<= 2` hours using `AGENT-TEMPLATE.md` and `boomopen doctor` | High onboarding friction could slow community contributions | Contributor feedback and PR turnaround review |

## Open Questions

|----|----------|---------|---------|----------------------|
| OQ-001 | How should standardized end-to-end benchmarks be structured to empirically test the 70%/70%/85% design targets? | CLI gates are unit/E2E tested (`34` suites), but live LLM productivity deltas lack a public benchmark harness | High | Define reproducible benchmark tasks comparing baseline solo prompting vs. `v5.5.0` Smart-Hybrid workflows |
| OQ-002 | Should a curated snapshot cache be documented for teams operating in air-gapped environments without `skills.sh`? | The `1,462` bundled skills already work 100% offline, so only external `npx skills` discovery is affected | Low | Document explicit air-gapped offline guarantees in `README.md` and `SKILLS.md` |
| OQ-003 | Should `matrix-skills/_dynamic.yaml` trust transitions gain a dedicated `boomopen` CLI subcommand in a post-`v5.5.0` release? | Currently schema-defined and manually curated | Medium | Evaluate adding deterministic CLI promotion helpers in a future release |
| OQ-004 | How should organizations measure `>= 80%` 30-day team adoption while preserving the zero-telemetry guarantee? | Built-in phone-home telemetry is an explicit non-goal | Medium | Recommend `.boomopen.json` repo adoption + internal engineering surveys |
| OQ-005 | What minimal live-LLM smoke matrix should be run manually before major releases across all 5 platforms? | `cli/*.test.js` validates static contracts and CLI compilers; live LLM behavior requires platform sessions | Medium | Maintain a 5-platform release checklist exercising Mode A, `/plan`, `/cook:team`, and `/conduct` |

| OQ-008 | Can `PreToolUse`/`Stop` hook enforcement (`--with-hooks`) be extended beyond Claude Code as other platforms standardize hook APIs? | `boomopen` CLI gates enforce post-artifact/post-wave invariants; hooks catch unsafe calls pre-execution and on stop | Medium | Track hook API parity across Cursor, Codex, Copilot, and Antigravity |
| OQ-009 | How should `boomopen conduct` prioritize newly added external CLI engines as ecosystems evolve? | Currently orchestrates `claude`, `codex`, and `antigravity`/`gemini` CLI engines | Low | Extend `cli/conductor.js` adapter table as new headless agent CLIs mature |
| OQ-010 | Is the `<= 2`-hour contributor onboarding target (BG-010) consistently met for first-time contributors? | Validated informally via templates and `boomopen doctor`, not yet measured via user study | Low | Collect feedback on early external PRs and refine `AGENT-TEMPLATE.md` if needed |
