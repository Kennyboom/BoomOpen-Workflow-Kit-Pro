## Functional Requirements

### Core Infrastructure & CLI Suite

| Req ID | Requirement | Priority | INVEST Score | Stakeholders | Goals |
|--------|-------------|----------|--------------|--------------|-------|
| BR-001 | Framework installs from a source-only Git clone (`git clone https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro.git && cd BoomOpen-Workflow-Kit-Pro && node cli/install.js install <tool\|--all>`) with SHA-256 ownership manifests (`~/.boomopen/manifests/<tool>.json`) and automatic user backups (`~/.boomopen/backups/`) | Must | 29/30 | S1, S2 | BG-001, BG-002 |
| BR-002 | Framework unifies 5 platforms: Antigravity (Gemini), Claude Code, OpenAI Codex, Cursor, and GitHub Copilot | Must | 24/30 | S5 | BG-002 |
| BR-023 | `boomopen` CLI provides 12 deterministic subcommands (`install`, `uninstall`, `list`, `settings` + `--ui` port `4567`, `doctor`, `check`, `research`, `design`, `plan`, `cook`, `ledger`, `conduct`) | Should | 27/30 | S1, S2, S6 | BG-001, BG-004 |

**Acceptance Criteria (BR-001)**: Given a machine with Node.js `>= 18.0.0`, when the user runs `git clone https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro.git && cd BoomOpen-Workflow-Kit-Pro && node cli/install.js install --all`, then verified kit bundles are installed at `~/.gemini/config/skills/boomopen-workflow-kit/`, `~/.claude/skills/boomopen-workflow-kit/`, `~/.codex/skills/boomopen-workflow-kit/`, `~/.cursor/skills/boomopen-workflow-kit/`, and `~/.copilot/skills/boomopen-workflow-kit/`, SHA-256 ledgers exist in `~/.boomopen/manifests/`, and exit code is `0`.

**Acceptance Criteria (BR-002)**: Given the repository is cloned, when `boomopen install <platform>` runs for `antigravity`, `claude`, `codex`, `cursor`, or `copilot`, then the platform's global entrypoint (`~/.gemini/GEMINI.md`, `~/.claude/CLAUDE.md`, `~/.codex/CODEX.md` + `config.toml`, `~/.cursor/CURSOR.md` + `rules/boomopen-workflow-kit.mdc`, or `~/.copilot/COPILOT.md` + VS Code prompt) is written with non-destructive `BOOMOPEN-SETTINGS` markers and passes `boomopen doctor --platform <platform>`.

| BR-011 | Tiered Execution: `TIER 1` native parallel sub-agents + Warm Session Reuse (`send_message`) in Mode B; `TIER 0` direct execution strictly for `<= 2` known files (Mode A); `TIER 2` embodiment fallback only when sub-agent tools are absent | Must | 24/30 | S4 | BG-003, BG-005 |
| BR-012 | Smart-Hybrid governance laws, Cognitive Load Sharding (`<= 3–4 OWNED_FILES` per shard), Anti-Patterns `A1–A14`, and deterministic CLI gates (`research`, `design`, `plan`, `cook`, `check --strict-phase --no-stubs`) enforced | Must | 19/30 | S4, S6 | BG-004, BG-006 |
