## Problem Statement

AI coding assistants (Antigravity/Gemini, Claude Code, OpenAI Codex, Cursor, GitHub Copilot) are capable individually, yet out of the box they operate as single generalist sessions without shared orchestration contracts. Engineering individuals and teams face three compounding problems:

1. **Repetitive prompt engineering & context bloat**: Every repository and multi-step feature requires re-explaining architecture rules, coding standards, and handoff formats from scratch. Sequential solo file crawling bloats the primary context window and degrades reasoning quality across waves.

2. **Lack of specialist depth & cognitive sharding**: A single unsharded prompt attempts database modeling, API contracts, UI token architecture, security auditing, and E2E verification simultaneously, overloading the context window whenever tasks span `> 2` files or `>= 2` domains.

3. **Lack of deterministic governance at scale**: Teams lack machine-verifiable gates for research citations, UI design contracts, DAG wave ownership locks (`OWNED_FILES` / `READ_ONLY_FILES`), stub/test-gaming prevention, and adversarial multi-agent or cross-engine review (`Author != Critic`).

The cost compounds across elapsed delivery time, regression defects, wasted context tokens, and unverified AI-generated artifacts.

## Business Goals

### BG-001: One-Time Global Setup

| Attribute | Detail |
|-----------|--------|
| **Goal** | Enable one-time source-only global setup that works automatically across workspaces |
| **Rationale** | Mandatory per-project boilerplate creates adoption friction. Installing once into user-level AI tool directories (`~/.gemini/`, `~/.claude/`, `~/.codex/`, `~/.cursor/`, `~/.copilot/`) with SHA-256 ownership manifests (`~/.boomopen/manifests/<tool>.json`) activates the kit everywhere while keeping project Git trees clean. |
| **KPI** | Installation success rate `>= 99%` across macOS, Linux, and Windows; zero mandatory per-project config files (optional `./.boomopen.json` override supported) |
| **Priority** | Must |
| **Requirements** | BR-001 (global source install), BR-023 (`boomopen` CLI management suite) |
| **Features** | BF-001 (one-time install), BF-023 (CLI status/list/settings/doctor) |

## Non-Goals

The following are explicitly NOT objectives for BoomOpen Workflow Kit `v5.5.0`:

| Non-Goal | Rationale |
|----------|-----------|
| Replace human developers | The framework amplifies developer velocity and review rigor; architectural ownership and final approval remain human-governed |
| Publish to the public npm registry | Distribution is intentionally source-only via Git (`https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro` · `https://boomopen.com`, `.releaserc.json` sets `npmPublish: false`) |
| Operate a hosted cloud backend or SaaS API | No cloud servers, user accounts, or subscriptions; the only HTTP listener is the opt-in local loopback Settings UI (`127.0.0.1:4567` via `boomopen settings --ui`) |
| Require an external database engine | All configuration, manifests, and project state live in portable local Markdown, YAML, TOML, and JSON files (`~/.boomopen/`, `.boomopen/project-ledger.json`) |
| Develop a standalone mobile client | The kit installs into desktop/CLI AI coding assistants (though it includes `mobile-engineer`, `mobile-team`, `mobile-design`, and `mobile-developer` to help users build mobile apps) |
| Guarantee benchmarked productivity percentages | Claims of 70%/70%/85% are architectural design targets rather than SLA-backed measurements |
| Bundle third-party external registries (`skills.sh`) | The `1,462`-skill local vault works offline; external `npx skills` discovery is strictly optional |
| Collect telemetry or analytics | Zero phone-home tracking or usage telemetry is included |

### Out of Scope

| Component | Reason for Exclusion |
|-----------|----------------------|
| Cloud backend or hosted API | Kit runs locally inside developer environments; no remote server infrastructure |
| External database server | State is persisted in local files (`~/.boomopen/settings.json`, `~/.boomopen/manifests/*.json`, `.boomopen/project-ledger.json`) |
| Public npm registry package | Explicitly disabled (`npmPublish: false` in `.releaserc.json`); distributed via source-only Git clone |
| Native mobile IDE client | Targets desktop and CLI AI coding assistants |
| Custom LLM model training or fine-tuning | Operates via structured instruction architecture, tool orchestration, and deterministic CLI compilers |
| `skills.sh` registry hosting | External community service; not operated or bundled by this repository |
| Usage telemetry or analytics | Excluded to preserve 100% local privacy and zero network dependency during installation |
