## Zero-Database File & Ledger Storage Philosophy

BoomOpen Workflow Kit (`@boomopen/workflow-kit` `v5.5.0`) requires **no SQL/NoSQL database, no external HTTP backend, no ORM, and zero runtime npm dependencies**. Instead, it combines two deterministic storage layers on the local filesystem:

1. **Declarative Instruction & Knowledge Assets** (`.md`, `.yaml`, `.toml`, `.mdc`): Specialist personas, flat workflow routers/variants, on-demand governance rules, and the `1,462`-skill vault read directly by AI coding models.
2. **Deterministic JSON Indexes & Cryptographic Ledgers** (`.json`): Pre-compiled `O(1)` skill lookup (`matrix-skills/compact-index.json`), 3-surface user settings (`~/.boomopen/settings.json` + `./.boomopen.json`), SHA-256 install manifests (`~/.boomopen/manifests/<tool>.json`), Multi-Session Autopilot phase/RTM ledgers (`.boomopen/project-ledger.json`), and Cross-Engine Conductor synthesis artifacts (`.boomopen/conductor/runs/`).

```json
      "path": "skills_library/senior-ml-engineer/SKILL.md"
    }
  }

```

### `matrix-skills/{domain}.yaml` & `_dynamic.yaml`

Each of the `19` domain YAML files stores rich relevance mappings (`1,476` domain entries resolving to `1,462` unique skills across `skills/` and `skills_library/`), while `_dynamic.yaml` tracks externally installed skills (`owner`, `checksum`, `support_state`, `promotion_state`, `freshness`, `installed_at`, `last_execution`):

```yaml
- skill_id: api-patterns
  category: core            # core | expert | specialized | utility
  priority_score: 10        # 1..10
  relevance_mapping:
    agents: [backend-engineer, tech-lead]
    profiles: ["backend:execution", "architecture:*"]
```

## Schema 4: SHA-256 Install Ownership Ledger (`manifests/<tool>.json`)

Managed by `cli/manifest.js`, every `boomopen install <tool>` writes `~/.boomopen/manifests/<tool>.json` (paths normalized relative to `~` with `/` separators) plus `<frameworkPath>/install-files.json`:

```json
{
  "format": 1,
  "kitVersion": "5.5.0",
  "files": {
    ".gemini/config/skills/skill-seeker/SKILL.md": "<sha256-hex>",
    ".gemini/agents/backend-engineer.md": "<sha256-hex>"
  },
  "dirs": [
    ".gemini/config/skills/skill-seeker",
    ".gemini/config/skills_library"
  ],
  "backups": {
    ".gemini/agents/custom-agent.md": ".boomopen/backups/antigravity/2026-11-10T04-00-00-000Z/..."
  },
  "legacyMoves": {}
}
```

- **Install / Upgrade Safety**: Existing files in shared directories are overwritten without backup only when their current SHA-256 matches `files[relPath]`. User-authored or user-edited files are backed up to `~/.boomopen/backups/<tool>/<timestamp>/` before replacement.
- **Uninstall Safety**: `boomopen uninstall <tool>` deletes only shared files whose on-disk SHA-256 still matches the manifest, restores pre-install backups, and preserves dotfiles symlinks.

## Schema 5: Multi-Session Project Autopilot Ledger (`project-ledger.json`)

Managed by `cli/ledger.js` (`boomopen ledger` and `boomopen plan compile`), `.boomopen/project-ledger.json` powers `/autopilot` across multi-day, multi-phase builds alongside `.boomopen/ROADMAP-PROGRESS.md` and `.boomopen/contracts/SHARED_CONTRACT.md`:

```json
{
  "schema_version": "5.5.0",
  "project_name": "Example Platform",
  "updated_at": "2026-11-10T04:00:00.000Z",
  "spec_documents": [
    {
      "path": "PLAN-billing.md",
      "sha256": "<sha256-spec-drift-guard>",
      "lines": 280
    }
  ],
  "active_cursor": {
    "current_phase_id": "PHASE-2",
    "baseline_passed_tests": 42
  },
  "phases": [
    {
      "phase_id": "PHASE-1",
      "title": "Wave 1 — Schema & Contracts",
      "depends_on": [],
      "status": "verified"
    },
    {
      "phase_id": "PHASE-2",
      "title": "Wave 2 — Parallel Feature Shards",
      "depends_on": ["PHASE-1"],
      "status": "in_progress"
    }
  ],
  "features": [
    {
      "req_id": "REQ-01",
      "phase_id": "PHASE-1",
      "title": "Lock billing DTOs & Zod contracts",
      "source_doc": "PLAN-billing.md",
      "agent": "backend-engineer#contracts",
      "owned_files": ["src/contracts/billing.ts"],
      "test_files": ["src/contracts/billing.test.ts"],
      "verification_cmd": "npm test -- billing.test.ts",
      "status": "verified",
      "passes": true
    }
  ]
}
```

- **SHA-256 Spec-Hash Drift Guard**: `boomopen ledger validate` and `boomopen ledger next` recompute the SHA-256 of every file in `spec_documents[]` and flag upstream specification edits immediately so downstream phases never code against stale contracts.
- **Monotonic Regression Ratchet**: `boomopen ledger verify` enforces `passed_tests >= baseline_passed_tests + |REQ(Phase_K)|` before advancing `active_cursor.current_phase_id`.

## Referential Integrity & Deterministic CLI Validation

Integrity across Markdown, YAML, TOML, and JSON schemas is enforced programmatically:

| Constraint / Relationship | Deterministic Validator |
|---------------------------|-------------------------|
| Instruction line limits (`entrypoints <= 250`, `rules <= 300`, `commands, agents, teams, i18n, and skills <= 450`), mojibake, legacy refs, & `compact-index.json` parity | `boomopen doctor` + `cli/docs-content.test.js` + `cli/doctor.test.js` |
| `RESEARCH-*` & `BRAINSTORM-*` citations, confidence tags, decision tables, & `HANDOFF_BRIEF` (`RES-G1..G4`) | `boomopen research validate` |
| `DESIGN-*` OKLCH tokens, 5-State UI matrix, WCAG 2.2 AA, & `DESIGN_CONTRACT` (`DESIGN-G1..G4`) | `boomopen design validate` |
| `PLAN-*` task schema, `<= 4 OWNED_FILES`/shard, collision-free parallel waves, acyclic DAG, & `AC-*` coverage (`PLAN-G1..G5`) | `boomopen plan validate` |
| Post-wave git `OWNED_FILES` / `READ_ONLY_FILES` lock compliance, non-empty deliverables, & anti-stub code quality (`COOK-G1..G4`) | `boomopen cook verify-wave` + `boomopen check --strict-phase --no-stubs` |
| Multi-session spec SHA-256 hashes, phase DAG acyclicity, & RTM completeness | `boomopen ledger validate` & `boomopen ledger audit` |
| `~/.codex/config.toml` syntax & role TOML integrity | `cli/codex-config.js` (parsed & verified before atomic write) |

## Data Lifecycle

| Operation | Mechanism |
|-----------|-----------|
| **Install (Source-Only)** | Clone `https://github.com/Kennyboom/BoomOpen-Workflow-Kit-Pro.git` and run `node cli/install.js install <tool\|--all>` (or `npm link` -> `boomopen install <tool\|--all>`). Writes `<frameworkPath>/`, merges marked entrypoint blocks, backs up conflicting shared files, and writes `~/.boomopen/manifests/<tool>.json`. |
| **Configure** | Run `boomopen settings set <key> <value>`, `boomopen settings preset <name>`, `boomopen settings --ui` (port `4567`), or `/settings`. Updates `~/.boomopen/settings.json` (or `./.boomopen.json`) and syncs AOT blocks in `< 10ms`. |
| **Runtime Read & Execute** | AI coding platform loads its `<= 250`-line entrypoint on Turn 1, resolves skills via `<skills>` + `matrix-skills/compact-index.json`, validates artifacts via `boomopen research\|design\|plan\|cook`, and writes transient deliverables to `<appDataDir>\brain\<conversation-id>\` (or `./reports/{topic}/`). |
| **Upgrade** | Run `git pull` inside `BoomOpen-Workflow-Kit-Pro` and re-run `boomopen install <tool\|--all>`. Obsolete unmodified kit files are pruned automatically via manifest diffing. |
| **Uninstall** | Run `boomopen uninstall <tool\|--all>`. Removes `<frameworkPath>/`, strips marked instruction blocks, deletes only unmodified manifest-tracked files, and restores user backups. |
